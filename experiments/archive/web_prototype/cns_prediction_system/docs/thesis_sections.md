# 论文可用文字

## 性能测试、功能测试、单元测试与压力测试

为验证中枢神经系统感染风险预测临床辅助决策原型系统的可用性、稳定性和业务闭环完整性，本文从功能测试、单元测试、性能测试和压力测试四个方面对系统进行验证。测试环境为本地开发环境，后端采用 Python Flask，数据库采用 SQLite，前端采用 HTML、CSS、JavaScript 与 ECharts。测试对象包括登录认证、患者管理、病例录入、静态预测、动态预测、历史预测保存、趋势图展示、报告生成、模型版本展示和操作日志记录等核心模块。

功能测试主要采用黑盒测试方法，围绕医生实际使用流程设计测试用例。首先测试未登录状态下访问内部页面是否会自动跳转至登录页；随后使用默认医生账号和管理员账号分别登录系统，验证不同角色的访问权限。患者管理模块测试患者新增、患者编号重复校验、患者列表查询和患者详情展示。病例管理模块测试单次病例录入、同一患者多时间点病例录入和病例详情查看。预测模块测试新增病例后自动生成静态预测结果，当同一患者病例记录达到两条及以上时自动生成动态预测结果，并检查预测结果是否写入历史记录表。报告模块测试患者基本信息、病例摘要、最新预测结果、关键影响指标、临床提示和辅助决策声明是否完整展示。权限模块测试普通医生无法访问操作日志，管理员可以查看日志与账号管理页面。测试结果表明，系统主要功能能够按照预期完成，满足临床辅助决策原型系统的基本流程要求。

单元测试主要针对后端核心业务函数进行验证。风险等级函数 `get_risk_level` 根据 0.3 和 0.7 两个阈值将风险概率划分为低风险、中风险和高风险。静态预测函数 `predict_static` 加载 PGFormer 静态模型权重和静态特征标准化器，根据脑脊液白细胞、脑脊液蛋白、脑脊液葡萄糖、CRP、PCT、体温和 GCS 等指标生成风险概率、关键影响因素和临床提示。动态预测函数 `predict_dynamic` 加载 D-PGFormer 动态完整模型和动态趋势特征标准化器，根据同一患者多时间点脑脊液白细胞、蛋白、葡萄糖和中性粒细胞比例的变化趋势生成动态修正值和融合风险。批量导入解析函数针对静态基础数据表和动态曲线数据表分别进行字段识别，验证 `ID`、`time`、`WBC_1`、`C_RBC_1`、`C_N_1`、`C_G_1`、`C_P_1` 等字段能够正确映射到患者和病例记录。测试结果表明，核心函数在正常输入、缺失输入和多时间点输入下均能返回结构化结果。

性能测试重点关注页面响应时间、数据库读写效率和自动预测流程耗时。在本地环境下，登录页、首页、患者列表页和模型版本页主要执行少量查询，响应时间较短。患者详情页需要查询患者基本信息、病例记录和历史预测结果，并生成趋势图所需 JSON 数据；在原型数据规模下能够保持较好的响应速度。新增病例流程包括病例写入、静态预测、必要时执行动态预测、预测结果保存和患者当前风险状态更新。系统启动时会加载 PGFormer 静态模型、D-PGFormer 动态模型及相应标准化器，单次预测阶段主要执行特征构造、标准化和模型前向推理。批量导入功能在导入静态基础数据表和动态曲线数据表时，会按患者 ID 创建或复用患者，并逐条写入病例和预测结果。测试表明，在毕业设计原型场景的数据规模下，SQLite 能够满足系统演示和基本验证需求。

压力测试采用模拟连续导入和连续录入的方式进行。测试数据包括静态基础数据表和动态曲线训练表，其中静态表可解析 913 个患者分组和 915 条病例记录，动态阳性曲线表可解析 141 个患者和 477 条时间点病例，动态阴性曲线表可解析 236 个患者和 748 条时间点病例。系统在解析上述文件时能够正确识别患者 ID 和多时间点检测数据，并按照既定规则触发静态预测和动态预测。由于 SQLite 是轻量级本地数据库，不适合高并发写入场景，因此本系统的压力测试定位于原型验证而非医院生产级并发验证。若后续进入真实临床系统开发阶段，可将数据库替换为 MySQL 或 PostgreSQL，并引入连接池、异步任务队列和模型推理服务，以提升并发处理能力和系统可扩展性。

综合测试结果表明，本系统能够完成医生登录、患者管理、多时间点病例管理、自动风险预测、趋势分析、报告展示、日志记录和模型版本管理等核心功能。系统在原型规模下具有较好的可用性和稳定性，能够支撑毕业设计答辩中的流程演示和功能验证。

## 原型系统设计

本系统定位为中枢神经系统感染风险预测临床辅助决策原型系统，面向神经外科、神经内科和感染相关科室医生，目标是在患者脑脊液和血液检测数据基础上提供感染风险预测、趋势分析和辅助决策报告。系统不直接替代医生诊断，而是作为临床辅助参考工具，帮助医生快速查看患者当前风险状态、历史检测变化和模型提示信息。

系统整体采用 B/S 架构。后端使用 Python Flask 框架实现路由控制、业务逻辑处理和模板渲染；数据库使用 SQLite 存储用户、患者、病例、预测结果、操作日志和模型版本信息；前端使用 HTML、CSS、JavaScript 和 Jinja2 模板引擎构建页面；趋势图采用 ECharts 实现风险概率和核心指标变化的可视化展示。该技术路线部署简单、结构清晰，适合毕业设计原型系统开发和后续模型替换。

系统功能模块主要包括用户认证模块、患者管理模块、病例管理模块、预测服务模块、趋势可视化模块、报告生成模块、模型版本模块和日志审计模块。用户认证模块负责医生和管理员登录，密码使用哈希方式存储，未登录用户访问内部页面时会被重定向至登录页。患者管理模块支持患者新增、查询、详情查看和批量导入。病例管理模块支持同一患者多时间点检测数据录入，字段包括基础临床信息、血液指标和脑脊液指标。预测服务模块在新增病例后自动调用静态预测函数，当同一患者病例数量达到两条及以上时进一步调用动态预测函数。趋势可视化模块根据历史预测结果和核心脑脊液指标绘制风险趋势图和指标趋势图。报告生成模块汇总患者基本信息、病例摘要、最新预测结果、关键影响指标、临床提示和辅助决策声明，并支持浏览器打印保存 PDF。模型版本模块用于展示当前静态模型和动态模型版本信息。日志审计模块记录登录、患者新增、病例新增、批量导入、重新预测和报告查看等关键操作。

数据库设计围绕临床业务流程展开。`users` 表保存医生和管理员账号；`patients` 表保存患者基本信息和当前风险状态；`cases` 表保存患者不同时间点的检测记录；`predictions` 表保存静态预测和动态预测历史结果；`operation_logs` 表记录用户关键操作；`model_versions` 表保存模型名称、版本、类型和状态。通过患者 ID 将患者、病例和预测结果关联起来，能够支持同一患者多时间点病例记录和历史预测追踪。

系统核心业务流程为：医生登录系统后创建或导入患者信息，在患者详情页新增病例检测记录；系统保存病例后自动调用静态风险预测函数并保存预测结果；若该患者已有两条或以上病例记录，则系统进一步调用动态风险预测函数，结合多时间点脑脊液指标变化趋势生成动态融合风险；最后系统更新患者当前风险概率和风险等级，并在患者详情页展示历史预测结果、风险趋势和核心指标趋势。该流程实现了从数据录入、模型预测、结果保存到报告展示的完整闭环。

界面设计采用蓝白色医疗系统风格，整体布局包括左侧导航栏、顶部用户信息栏和主内容区。首页展示总患者数、今日新增患者数和高风险患者数，并集中展示高风险患者列表。患者详情页以患者基本信息卡片、病例时间轴、病例记录列表、历史预测记录和趋势图组成，便于医生快速掌握患者病情变化。当患者仅有一次检测记录时，系统不展示风险趋势图和指标趋势图，避免在缺乏多时间点数据时产生误导。报告页采用适合打印的结构，集中呈现患者信息、病例摘要、最新预测结果、关键影响指标、临床提示、模型版本和辅助决策声明。

在安全性方面，系统实现了基础登录状态校验、密码哈希存储、角色权限控制和操作日志记录。普通医生可以进行患者和病例管理，管理员可以查看操作日志并管理系统账号。考虑到医疗系统账号通常由机构统一分配，系统不提供公开自注册入口，而是在管理员页面中提供账号创建功能。该设计既满足原型系统演示需求，也符合医疗信息系统的基本权限管理思路。

系统当前已接入真实推理模型，静态模型名称为 PGFormer v1.0，动态模型名称为 D-PGFormer v1.0。静态推理加载 `best_fold1.pth` 和 `static_scaler_fold1.joblib`，根据单次病例的脑脊液指标、血液炎症指标和临床信息生成风险概率；动态推理加载 `dynamic_full_model_fold1.pth` 和 `dyn_scaler_fold1.joblib`，根据多时间点脑脊液指标变化趋势生成动态修正值和融合风险。系统将模型推理封装在 `predict_static` 和 `predict_dynamic` 两个接口中，因此后续继续更新模型权重时，只需保持输入输出结构一致，即可在不改变页面和数据库结构的情况下完成模型升级。
